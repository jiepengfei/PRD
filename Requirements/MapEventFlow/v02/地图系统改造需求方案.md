# 地图系统改造需求方案

版本：v0.2 · 日期：2026-11-03 · 状态：需求整理与实施方案，尚未实施。

本稿依据最近一轮讨论收敛，作为本次地图事件改造的阅读入口。取代v0.1历史评审稿中偏复杂的首版建议。保留既有地图系统与业务模块，先完成简单可复用的事件接入。

## 1. 需求一句话

**在指定地图砖块上绑定事件，满足条件时，通过到达或主动交互触发；事件可以播放CG、对白、启动战斗、解锁宝箱、解锁传送等。多个步骤以数组存储，按顺序执行。**

未来在已经支持的行为类型范围内新增内容，应主要通过配置完成。新增底层行为仍需要增加对应执行能力。

## 2. 已确认的规则

1. 图标只负责展示，不参与业务判断。事件可以没有图标，换图标不改变事件逻辑。
2. 展示条件、触发条件分开。允许“显示但暂时不可交互”，也允许隐藏的剧情触发点。
3. 条件读取游戏当前状态；通过稳定字段标识访问，不直接依赖存档文件内部结构。存档负责保存和恢复这些状态。
4. 触发条件不满足时不执行事件、不拦截移动，砖块仍按原有地形规则通行；就事件而言相当于空白砖块。
5. 流程步骤按数组顺序执行，完成当前项才进入下一项。已完成内容记录进度，不重复执行。
6. 增加“完成后移除”配置，移除的是当前事件入口；完成记录保留，其他人物或事件不随之删除。
7. 对话使用通用组件，背景可选，可以直接叠在当前地图上。
8. 复用实际工程的地图、对话、CG、战斗、任务、背包、UI管理和存档，补接线与必要能力，不重新制作全部系统。

原讨论中的“执行阶段”在本稿中指玩家当前执行到哪个步骤，作为运行进度保存；步骤先后由数组顺序表达，不再重复配置“下一步编号”。

## 3. 采用的简单结构

```text
地图砖块上的事件入口
  ├─ 在哪里：地图ID、坐标
  ├─ 何时触发：到达 / 交互 / 地图就绪
  ├─ 能否触发：条件
  └─ 执行什么：流程ID
                 ↓
              步骤数组
        CG → 对白 → 战斗 → 解锁
                 ↓
             完成并保存
```

制作时分为两份数据：

- **地图事件配置**：指定位置、触发方式、条件、流程引用及完成后的处理。
- **流程配置**：指定各步骤调用哪个系统、加载哪份内容。

首版先验证“一个事件入口引用一条流程”，不加入多层事件队列、候选事件优先级、嵌套流程或复杂分支。同格多个独立事件的通用调度暂不作为首版必做；保持已有地图目标的兼容性，不额外破坏旧功能。

## 4. 地图事件字段

以下是建议契约，英文名供实施映射；最终文件命名、目录与服务命名服从工程规范。

| 字段 | 含义 |
| --- | --- |
| `eventId` | 稳定事件ID，用于查询进度、保存和防重 |
| `mapId` | 所属逻辑地图ID |
| `cell` | 砖块逻辑坐标，不使用预览图像素坐标 |
| `trigger` | 触发方式 |
| `showWhen` | 展示条件，仅控制该入口对应的图标/提示展示 |
| `triggerWhen` | 触发条件，决定是否可以启动流程 |
| `flowId` | 所关联的流程配置ID |
| `removeOnComplete` | 流程全部成功完成后，是否移除当前事件入口 |

图标资源、位置、尺寸继续复用已有展示配置，例如 `mapSpriteId`；没有图标也可以建立事件入口。禁止用图标是否生成成功来判断事件是否存在。

### 触发方式

| 值 | 检查时机 | 示例 |
| --- | --- | --- |
| `arrive` | 玩家实际到达砖块后 | 山贼遭遇、剧情点 |
| `interact` | 玩家主动发起既有交互操作时 | 宝箱、NPC、传送 |
| `mapReady` | 地图、存档与角色初始化完成后，检查角色当前所在砖块 | 隐藏开场事件 |

条件满足只表示具备资格，不自动等同于开始。首版不每帧扫描全部事件，不因远处条件变化强行打断玩家；在触发时重新校验，相关状态变化时刷新必要的展示与可交互状态。

沿用现有到达入口，普通移动与免费重访传送的到达通知均需接入同一检查，禁止绕过触发判断；每次实际到达只产生一次事件启动机会，不重复分派。未揭示砖块的图标仍遵守原有迷雾规则，`showWhen` 不能提前泄露隐藏地图内容。

### 条件表达

首版只需要简单的“字段等于某值”，字段值来源于统一的当前状态读取接口。

```json
{
  "field": "story.openingCompleted",
  "equals": true
}
```

建议默认值：不配置条件表示不附加限制；配置了条件却找不到字段或类型不匹配，报告配置错误，不能当作满足。暂不引入任意表达式、脚本、嵌套条件树。

`showWhen` 通过不代表可触发；`triggerWhen` 通过也不强制显示图标。入口已完成后，仍受完成状态约束，不能仅凭条件再次启动。

## 5. 流程字段与行为类型

| 字段 | 含义 |
| --- | --- |
| `flowId` | 整段流程ID |
| `steps` | 按顺序执行的步骤数组 |
| `steps[].type` | 调用哪个系统或行为执行器 |
| `steps[].contentId` | 加载的具体内容或目标ID |

`contentId` 对应原讨论中每项的“流程id”：CG步骤引用CG配置，对白步骤引用对白配置，战斗步骤引用遭遇配置，解锁步骤引用目标配置。整段 `flowId` 用于地图引用，二者不要混为一层。

首版需要接入的行为：

| 行为 | 作用 | 完成依据 |
| --- | --- | --- |
| `cg` | 播放图片或视频CG，媒体类型在CG配置中定义 | 自然播放结束或允许的跳过完成 |
| `dialogue` | 播放指定对白 | 全段完成或允许的跳过完成 |
| `battle` | 启动既有战斗 | 战斗模块报告胜利 |
| `unlockChest` | 将指定宝箱设为可交互 | 解锁状态提交成功 |
| `unlockTeleport` | 将指定传送入口设为可交互 | 解锁状态提交成功 |
| `teleport` | 使用指定传送配置移动角色 | 既有传送业务报告成功 |

宝箱“解锁”和“开箱领奖”是不同操作；传送“解锁”和“实际传送”也是不同操作。解锁不自动发奖或移动角色。宝箱内容、目标地图、目标坐标等具体业务数据继续放在所属系统配置里，不复制进地图事件字段。

其他能力后续增加执行器并登记类型，例如奖励、任务、商店入口。首版不因为“等等”就要求一次实现所有业务模块。

入口条件控制流程是否开始，流程启动后不因入口条件变化自动中断。首版不为每个步骤配置一套触发方式或条件；确实需要的条件步骤以后再扩展。

## 6. 调度器的最小职责

只需要一个薄的地图事件调度器，负责：

1. 找到当前砖块绑定的事件，校验触发方式、条件及完成记录。
2. 防止重复启动，停止当前移动，取得既有流程输入权限。
3. 读取流程，启动当前未完成步骤，等待对应系统返回。
4. 成功后保存该步完成进度，再执行下一步。
5. 全部成功后保存事件完成；按配置移除入口，并释放流程占用。

执行器通过完成回调或现有返回接口通知调度器即可。已有事件总线可以复用，但本需求不强制新增一套全局订阅架构。

首版建议采用以下统一默认行为，属于实施默认而非额外玩法需求：

- 返回成功才推进；失败、撤退、关闭或中断不当作成功。
- 同一时刻只允许一个占用玩家操作的地图事件流程，新触发不并发叠开，当前事件完成后不复用同一次点击再启动其他事件。
- 战斗失败停在战斗步骤，按既有战斗规则返回地图；下次合法触发时重试该步，前面对白不重播。
- 传送先支持原有同地图能力。跨地图传送若实际已有接口则接入；否则明确列出依赖。首版把会切地图的传送放在流程最后一步，避免提前引入跨地图流程续跑。
- 已完成事件首版不重复执行。`removeOnComplete=false` 仅表示保留入口/表现，不表示允许无限重播；周期事件、重复刷取另行扩展。

失败后HP、行动点、奖励和返回位置遵循对应业务模块，不由地图调度器另造一套规则。

## 7. 进度、完成与输入保护

配置描述“要做什么”，存档描述“已经做了什么”，二者分开。

最小运行记录示意：

```json
{
  "eventId": "bandit_01_event",
  "currentStep": 1,
  "completed": false,
  "removed": false
}
```

例如第0步对白已完成，第1步战斗尚未完成，`currentStep=1`。退出重进后不重播第0步，下一次合法触发从第1步开始。`mapReady`类开场在地图就绪时可自动恢复，其他事件不强制读档立刻开播。

- 不要求视频精确到秒、对白精确到字恢复；未完成步骤允许从该步开头重播。
- 正常播放、跳过、重复回调、重进地图不能重复提交已完成业务。
- 步骤进度和业务结果沿既有保存与防重机制提交；不能在保存失败时仍清除进度或继续下一步。若现有入口无法协调提交，应明确补最小适配。
- 移除事件后保留完成记录，读档不能重新生成同一事件入口；不删除无关NPC、砖块或整个目标列表。
- 首版使用步骤下标保存时，已用于验收存档的步骤数组不能无迁移地插入、删除或重排。编辑测试内容优先新测试档，保留原存档。
- 地图进度独立于界面显隐，关闭一个窗口不等于事件完成。

对白、CG和战斗交接期间沿用现有UI栈/模态机制。准备视频时也阻止地图行走与点击穿透；步骤交接不得短暂释放输入导致一键两用；流程退出后清理自身资源和输入占用，不清掉其他窗口的权限。

## 8. 配置示例

以下是说明结构的示例，不是当前工程可直接读取的既有配置。坐标、内容ID、状态字段均需映射实际工程，不作为正式内容验收数据。

### 8.1 地图事件

```json
{
  "events": [
    {
      "eventId": "bandit_01_event",
      "mapId": "novice_village",
      "cell": { "x": 8, "y": 9 },
      "trigger": "arrive",
      "showWhen": { "field": "story.openingCompleted", "equals": true },
      "triggerWhen": { "field": "story.openingCompleted", "equals": true },
      "flowId": "bandit_01_flow",
      "removeOnComplete": true
    }
  ]
}
```

`events`在这里是地图事件清单，不表示多个事件会因一次到达全部顺序播放；自动顺序执行的是各流程内部的`steps`。

### 8.2 事件流程

```json
{
  "flowId": "bandit_01_flow",
  "steps": [
    { "type": "dialogue", "contentId": "bandit_01_before" },
    { "type": "battle", "contentId": "bandit_01_encounter" },
    { "type": "dialogue", "contentId": "bandit_01_after" },
    { "type": "unlockChest", "contentId": "mountain_chest_01" },
    { "type": "unlockTeleport", "contentId": "village_teleport_01" }
  ]
}
```

该示例用于验证“对白→战斗→对白→解锁”的通路，不表示正式Demo一定要把宝箱和传送都绑定第一战。

### 8.3 最小用例

| 砖块事件 | 条件及操作 | 执行内容 |
| --- | --- | --- |
| 隐藏开场 | 开场未完成，角色所在练剑场地图就绪 | 练剑CG视频→报信对白 |
| 山贼遭遇 | 开场已完成，角色到达 | 对白→战斗→战后对白 |
| 宝箱 | 已被解锁，玩家主动交互 | 调用已有开箱业务；不把“显示图标”当作已经领奖 |
| 传送入口 | 已被解锁，玩家主动交互 | 调用已有传送业务 |

开场完成可通过统一事件完成记录提供稳定状态字段；若既有内容仍使用`openingCompleted`，由状态适配同步/映射，不能产生两份互相冲突的完成真源。

## 10. 实施步骤

### 第一步：核对接口，确定配置契约

读取家里实际工程、项目规范与未提交改动，确认到达、交互、对白/CG结束、战斗结果、开箱、传送、状态与保存入口。沿既有目录确定新增文件；输出真实复用点及缺失接口，不只重新写一遍架构方案。

### 第二步：完成地图事件最小核心

实现事件配置读取、状态字段查询、展示/触发条件、调度器、当前步骤及完成保存。用无图标事件和一个已有对白验证，不先扩展全部系统。

### 第三步：接入已有行为

接CG/视频、对白、战斗、宝箱解锁、传送解锁和已有传送能力。执行器只适配对应模块，不重做模块本身。缺少正式素材时使用明确的测试配置，测试后恢复原存档，不留下验收奖励。

### 第四步：用配置跑通示例并回归

在测试地图/测试档验证“对白→战斗→战后对白→解锁”，再把已有练剑视频与报信内容绑定隐藏开场入口。第二条不同流程应主要新增配置，不能再创建专用剧情控制器。

以上是分步实施范围，不代表本次文档请求已授权开始修改工程。

## 11. 验收清单

| 场景 | 通过标准 |
| --- | --- |
| 同一能力新增事件 | 修改位置、条件、内容引用即可复用，无需新增专用控制代码 |
| 无图标事件 | 仍能在配置的触发时机启动；更换/隐藏图标不改变逻辑 |
| 条件不满足 | 不启动、不弹窗拦路、不扣事件费用，保持原有地形通行规则 |
| 展示与触发分离 | 可见但未解锁不执行；隐藏但允许的剧情点可以执行 |
| 数组执行 | 前一步成功后才进入下一步，不并发叠开、不重复响应回调 |
| 战斗失败 | 不播放胜利后续、不解锁目标；再次触发不重播前面已完成对白 |
| 宝箱解锁 | 解锁后可交互；解锁动作本身不发开箱奖励 |
| 传送解锁 | 未解锁不传送；解锁后通过现有传送规则移动 |
| 完成后移除 | 当前事件入口移除且读档不复活；其他对象不误删 |
| 完成后保留 | 对象可以保留，已完成事件不会因此再次启动 |
| 退出/读档 | 当前步骤恢复正确，已完成步骤和业务结果不重复提交 |
| 异常 | 未知类型、内容ID不存在、状态字段错误、保存失败有明确报错，不静默按成功推进 |
| 输入 | CG准备/播放、对白和系统交接期间无地图点击穿透，退出后无残留占用 |
| 原功能 | 探索、翻牌、免费重访、休息、旧事件与既有UI行为不回退 |

## 12. 本轮边界与交付物

本次地图改造先建立可复用的触发与执行能力。五日调度、悲愤、完整首领四层、访仙缘、村长与送别仍按《Demo完整流程需求》v02（独立文档，不在本次上传范围）另行逐步接入；不在这次顺手完成整套Demo。
