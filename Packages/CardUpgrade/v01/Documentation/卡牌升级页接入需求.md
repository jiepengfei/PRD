# 卡牌升级页接入需求

在战斗外接入牌组和背包两个入口。两者共用同一个选牌、升级预览和确认流程。视觉以 [无标题定稿](../Reference/card-upgrade-approved.png) 为准，组装参见 [美术资源与组装说明](美术资源与组装说明.md)。

## 两个入口

| 入口 | 打开方式 | 返回路径 |
| --- | --- | --- |
| 牌组 | 牌组 → 卡牌详情 →「升级」。携带已选卡，直接打开升级对照。 | 取消或右上角关闭回原卡详情。成功后也回到原卡详情，刷新卡面和升级状态。 |
| 背包 | 背包 → 选中「心得」→「使用」。打开复用现有牌组卡面展示的选牌页，选择目标后进入升级对照。 | 对照页取消或关闭回选牌页，再关闭回背包。成功后回背包并刷新心得余量。 |

背包的「使用」只启动选牌流程。打开页面、切换卡牌、取消和返回都不扣心得。战斗中和其他不允许改牌的状态沿用项目现有输入限制。胜利页继续展示掉落，玩家回到战斗外后从上述入口操作。

## 选牌与预览

- 选牌列表、当前卡和升级后预览卡直接引用工程现有卡牌预制件。保留已有新旧预制件和资源引用。两张对照卡分别绑定当前数据和下一阶段预览数据，预览不得改动持有卡或牌组。
- 沿用当前布局。两张卡居中，中间放箭头，后方卡牌退暗。下方显示心得图标、实际消耗与持有数量，以及「取消」「确认升级」。页面保持无标题、不加卡牌上方阶段标签。卡面阶段、数值、描述沿用原预制件。
- 优先按现有数据和规则筛选可升级目标。满级、无下一阶配置或当前规则不允许升级的卡不能进入有效确认。心得不足时仍可看可用预览，禁用确认并显示原因。背包选牌没有合法目标时显示空态，提供返回。
- 若工程允许同名卡分别成长，流程须保留选中的卡实例标识。若工程按牌种共享进度，则按原有粒度绑定。所有预览和升级成本用实际配置，定稿里的数字仅供排版参考。

## 确认与状态更新

- 点「确认升级」时重新校验卡牌仍持有、阶段未变、可升级、心得充足。由既有业务入口把扣心得和升级提交为同一结果。提交期间禁用重复确认。校验或提交失败时保持界面可操作，刷新实际状态并说明原因，不能出现只扣心得或只升卡。
- 本需求把心得的「使用」指向卡牌升级，并消耗实际配置的心得数量。若工程已有相冲突的心得经验用法，实施时先核对并说明冲突，避免同一次使用同时扣物并发放角色经验。升级阈值、升阶效果和具体消耗由实际配置决定，缺项在回执注明。
- 成功后刷新背包余量、牌组和卡详情，并沿用工程已有保存机制。界面只提交操作与显示结果，不另造卡牌或库存状态。

## 必要自检

1. 牌组打开指定卡的对照页，取消回原卡且心得数量不变。确认后卡面更新。
2. 背包使用心得先选牌，返回不扣材料。确认一次只扣对应数量并只升一次，回背包可见更新后的余量。
3. 检查心得不足和满级卡不能确认。完成必要编译和上述定点验证即可。
