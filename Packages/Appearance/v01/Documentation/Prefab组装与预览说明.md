# 外观窗口与实时预览的 Prefab 组装

## 窗口组件

沿用工程UI栈和已有窗口生命周期。下列名称描述组件职责，实际命名和目录遵循目标工程。

```text
AppearanceWindow
├─ 纸面背景与标题
├─ CategoryTabs
│  ├─ 战斗皮肤
│  └─ 卡牌风格
├─ SkinList
│  └─ SkinItem（按配置重复实例化）
│     ├─ 条目底板与选中侧线
│     ├─ 缩略预览区域
│     ├─ 名称与获取状态
│     └─ 实心绿色“✓ 使用中”标记
├─ SkinPreview（实际皮肤Prefab的隔离预览区域）
├─ 名称、状态、替换内容说明
└─ 应用按钮与结果反馈
```

SkinItem共用同一Prefab，由配置绑定名称、解锁状态、当前选择和实际使用状态。若已有预制件可承担同样职责，应优先复用。

## 实时皮肤预览

选中皮肤后，从配置中的实际资源引用取得对应战斗/卡牌Prefab，实例化到独立预览根。战斗用一份固定预览状态绑定背景、敌人视图、血条等皮肤组件。卡牌用同一组代表卡数据绑定所选整套风格，至少可看到多个正面与卡背。

预览所用资源与实际游戏使用同一套Prefab。缩略图可由同一个预览流程生成并缓存。若工程需要单独PreviewPrefab，仅允许它引用真实皮肤组件，避免与正式显示维护成两套样式。

依照现有渲染方式，UI皮肤可放进独立裁剪容器，场景/模型皮肤可使用隔离层、预览相机与RenderTexture映射到RawImage。先核对工程能力再选择实现。预览对象只接受展示用数据，生命、费用和状态由预览数据提供，避免自动运行战斗逻辑、写存档、结算奖励或接管地图输入。

切换选择时释放上一组预览对象及RenderTexture等占用，避免叠加摄像机或重复绑定。窗口关闭也执行相同清理。预览里只显示选中皮肤内容，尚未应用也能查看。

## 列表与应用状态

- 已获取皮肤可应用，未获取皮肤可预览并显示获取状态。
- “使用中”绑定实际生效选择。浏览其他皮肤时，原使用项仍保留绿色标记。
- 当前正在查看的条目显示选中底板及细侧线。已使用的条目优先显示使用中底板；如果也被选中，同时保留侧线。
- 右上显示对应分类当前使用的真实名称；右侧预览若就是实际使用项，也显示实心绿色“✓ 使用中”。
- 应用成功后更新列表、预览标记和当前使用名称。战斗皮肤与整套卡牌风格分别保存选择，按现有计划在下一场战斗使用。

皮肤配置提供稳定ID、分类、名称、实际Prefab引用及必要展示元数据，获取记录和使用选择来自真实持久状态。包内没有新增皮肤内容或解锁配置。

## 组装核对

在目标工程检查两类Tab、列表选中和使用中区别、未获取状态、Prefab预览切换及关闭清理。样式还原检查文字、图标边界和目标分辨率布局。按用户要求控制验证范围，围绕当前组件接线做必要检查即可。
