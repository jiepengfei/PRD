# 正式开场接入需求

日期：2026-11-03。当前流程：练剑视频 → 五句报信对白 → 恢复地图操作。

本稿替代旧开场包在触发接线、输入规则和恢复策略上的过时说明。复用本工程已接入的地图事件与通用对白能力；[地图改造需求](../../../Requirements/MapEventFlow/v02/地图系统改造需求方案.md)为结构参考，具体字段以当前实际实现为准。

## 1. 入口配置

- 在实际练剑场出生砖块绑定隐藏事件，使用工程已支持的地图就绪触发，不显示图标。
- 地图、角色和存档初始化完成后检查；角色位于绑定砖块、开场尚未完成时，启动开场流程。
- 使用稳定事件ID（建议`demo_opening_training`），将视频CG与报信对白按顺序配置。事件及流程文件名、字段名映射已有实现，不新造JSON加载器。
- 不重建地图、不移动旧存档角色到出生点，不增加第二个玩家。已完成该开场的存档不重新播放。

## 2. 练剑视频

- 使用包内`Assets/CG/cg_opening_training_v001.mp4`原件。若实际播放器需要规范化导入或转码，保留原件，另存工程运行版本并记录设置与映射。
- 通过既有加载方式取得素材，不硬编码本机路径。关闭循环，等比完整显示，可留边，不拉伸或裁掉人物与剑。
- 视频准备与播放期间保持流程输入保护，准备好有效画面再播放。
- 自然结束或点击“跳过”均完成视频步骤并进入报信对白；不能直接完成整段开场，也不能重复打开对白。
- 播放失败沿现有播放器的重试/跳过机制处理；若缺失，补最小恢复入口，不能无限黑屏或悄悄完成整段开场。跳过仍进入对白。
- 视频步骤结束后关闭视频层并停止音轨，显露当前地图；不要求循环视频或另画报信背景，不重复添加BGM。
- 切场景/窗口强制关闭属于中断，取消过时准备/播放回调，不伪造整段完成。

## 3. 五句对白

按以下顺序配置，姓名与正文由Unity文字组件显示，不烘焙进图片或视频。

| 顺序 | 说话人 | 正文 |
| --- | --- | --- |
| 1 | 主角 | 这一式，总算比昨日稳了些。 |
| 2 | 村民 | 少侠！村外发现了山贼，他们放话，五日内若不交粮，就要闯进村来！ |
| 3 | 主角 | 村里的口粮，哪能交给他们。 |
| 4 | 村民 | 已有山贼在村外的房屋附近徘徊，大家都不敢出去。 |
| 5 | 主角 | 我去看看。你先通知乡亲们，别单独出村。 |

- 直接使用当前地图背景和已接入的通用对话UI，保留现有布局、人物比例和组件动画。
- 主角立绘可复用工程已有资源；村民没有立绘时只显示姓名和正文，收起空立绘区域，不拿村长冒充、不把缺立绘设为阻塞。
- 继续和对话跳过复用既有交互。只在整段对白完成或明确跳过整段对白时，报告对白步骤完成。
- `Data/opening.example.json`保存相同五句正文；按实际Story数据契约映射，不将样例字段直接当既有API。

## 4. 结束、保存与输入

- 沿地图事件的步骤保存机制：已完成视频步骤不因退出重进而重播；未完成步骤按当前实现从该步起点恢复，不要求精确到秒或字。
- 整段对白结束后才完成开场事件并保存，按配置移除触发入口；兼容或映射已有`openingCompleted`，不要建立两个冲突的完成状态。
- 已完成事件再次进入地图不重播；重复回调、跳过与自然结束竞争只能提交一次结果；保存失败不能假装完成。
- 视频与对白交接期间保持输入保护，不能短暂放开地图；结束后清理自身音轨/媒体/输入占用，恢复当前地图，不释放其他窗口仍持有的权限。
- 操作沿家里工程现行规则：左键详情、中键移动、右键拖镜头；不得恢复旧版“右键移动”。
- 不接取任务、不登记期限、不发奖励、不改变正式敌群和后续地图进度。

## 5. 验收与交付

1. 新测试档在练剑场进入：真实视频 → 五句对白 → 当前地图可操作。
2. 跳过视频：只打开一次报信对白，不提前完成开场。
3. 视频/对白期间点击和Esc不穿透；结束后无黑屏、残留声音或输入锁。
4. 对白完成或明确跳过后保存成功；重进地图不重播。
5. 视频或对白中途退出后，按已有步骤进度恢复；完成步骤不重做。
6. 模拟资源/播放失败时可以恢复，且不会自动完成整段开场。
7. 村民无立绘仍能正常阅读与继续，正文和说话人正确。
8. 无新增主线、五日事件、战斗、悲愤或其他CG。

测试前备份主存档和备份档，测试后恢复并核对，不留下测试进度。交付实际配置与资源落点、必要适配代码、Unity运行截图与验证结果；未实际测试的项如实标明，不以静态校验代替运行验收。未经进一步授权不提交、推送或发布工程代码。
